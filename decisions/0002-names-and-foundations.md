# 0002 — Names, foundations and phase skills

2026-10-15 · status: accepted · decided by: Machiel Odendaal

## Situation
DDS Core joins several established frameworks. For other people and other AIs to use and extend it, each borrowed idea must be credited and each adaptation stated, and every term must have one name.

## Choice
- The method is **DDS: Design-Driven Specification**; this framework is **DDS Core**; the cycle is the **DDS Loop**: Capture → Organise → Distil → Express → Review → Capture.
- Foundations are credited in `spec/05-foundations.md`: CODE (Tiago Forte); Jobs to be Done (Clayton Christensen); job stories (Intercom; Alan Klement); Outcome-Driven Innovation's job map and desired outcomes (Anthony Ulwick; Lance Bettencourt); After-Action Review (US Army); Specification-Driven Development; Plan–Do–Check–Act (W. Edwards Deming).
- Every term is defined once in `spec/06-glossary.md`, with its origin.
- One skill per phase under `skills/`, so any agent can run the loop.
- British spelling for phase names in prose (Organise, Distil); Forte's originals (Organize, Distill) when citing him.

## Consequences
New terms go into the glossary in the same change that introduces them. A change that departs from a source framework says so in `05-foundations.md`.
